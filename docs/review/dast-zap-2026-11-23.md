# DAST with OWASP ZAP: first run, 2026-11-23 (S-179)

**Story:** S-179 · **Contract:** K-SEC-07 · **Compliance:** C03 · **Tool:** OWASP ZAP 2.16.1 (`ghcr.io/zaproxy/zaproxy:2.16.1`), API scan (passive and active rules) from each module's OpenAPI spec
**Status:** In Progress. A partial run before staging; the acceptance run is on staging (S-093).

## 1. Set-up

- **Command:** `task dast` (`tools/ci/zap-scan.sh`).
- **Target:** the whole Core API assembled by `backend/internal/app/dast_test.go` (build tag `dast`, never shipped). It runs on a test database with the fake vendors and synthetic people: a verified doctor with MFA and a practice, and a signed-in patient with consents.
- **Passes:** each module spec is scanned three times, once anonymous, once with the patient's token and once with the doctor's.
- **Reports:** written outside the repo, because they contain the synthetic tokens in request headers.

## 2. Result of this run

The run was **stopped part-way by the machine running low on memory**, not by a failure in the scan. 11 of 30 scans finished:

| Module spec | Anonymous | Patient | Doctor |
|---|---|---|---|
| admin | 0 FAIL, 114 PASS | 0 FAIL, 114 PASS | 0 FAIL, 114 PASS |
| booking (29 operations imported, 93 URLs walked) | 0 FAIL | 0 FAIL | 0 FAIL |
| clinical | 0 FAIL | 0 FAIL | 0 FAIL |
| consult | 0 FAIL | 0 FAIL | not finished |
| directory, identity, notifications, payments, records, verification | not run | not run | not run |

- **Warnings:** the only one in every finished scan is "ZAP is Out of Date" (10116), a notice about the scanner, not the API.
- **Rules:** none of the 114 active and passive rules raised a High, Medium or Low alert. They include SQL injection, path traversal, server-side template injection, remote OS command injection, XXE, application error disclosure and cloud metadata exposure.
- **Open High or Critical:** none in the finished scans.
