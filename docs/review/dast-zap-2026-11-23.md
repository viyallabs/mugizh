# DAST with OWASP ZAP: 2026-11-23 (S-179)

**Story:** S-179 · **Contract:** K-SEC-07 · **Compliance:** C03 · **Tool:** OWASP ZAP 2.16.1 (`ghcr.io/zaproxy/zaproxy:2.16.1`), API scan (passive and active rules) from each module's OpenAPI spec
**Status:** In Testing. A full local run is clean; the acceptance run is on staging (S-093).

## 1. Set-up

- **Command:** `task dast` (`tools/ci/zap-scan.sh`).
- **Target:** the whole Core API assembled by `backend/internal/app/dast_test.go` (build tag `dast`, never shipped). It runs on a test database with the fake vendors and synthetic people: a verified doctor with MFA and a practice, and a signed-in patient with consents.
- **Passes:** each module spec is scanned three times, once anonymous, once with the patient's token and once with the doctor's.
- **Reports:** written outside the repo, because they contain the synthetic tokens in request headers.

## 2. Result

**Second run (2026-11-23, complete):**
- **Coverage:** all 33 scans finished: 11 module specs, each anonymous, as the patient and as the doctor.
- **Result:** every scan ended **FAIL 0, PASS 114**, so no rule raised a High, Medium or Low alert. The only warning in each was "ZAP is Out of Date" (10116), a notice about the scanner, not the API.
- **Operations imported per spec:** booking 29, clinical 26, admin 21, consult 12; the rest were similar.
- **Reviews:** the routes answered 404, because the target runs the IN pack where the `reviews` flag is off (D-82).
- **Open High or Critical:** none.

The first run (same day) stopped part-way when the machine ran low on memory. Its 11 finished scans had the same result.
