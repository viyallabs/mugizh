# Load-test plan (k6) and mobile performance budgets (S-084)

**Phase P07 · Epic EP09 · Depends on:** S-065 ([performance-targets.md](../arch/performance-targets.md)) · **Date:** 2026-11-15
**Status:** Done (acceptance criterion: plan in /docs/test). It runs from Sprint 0 (S-101 harness) and is executed in S-175. Volumes marked [CONFIRM] depend on the founder's growth assumptions.

**Who this is for:** engineers writing the k6 scripts and mobile performance checks.

**Tool:** **k6** for API load. It is language-neutral, so it works whatever stack is chosen (ADR-25 lists it). Mobile checks use the platforms' own benchmark and profiling tools, **not third-party SDKs** (mobile rule M5).

## 1. Rules

1. **Never load-test production.** Use staging, scaled to production size for the run, with **synthetic data only** (S-044). A dedicated performance environment from the same infrastructure code is also acceptable.
2. **Synthetic data set:**
   - 50,000 clinics and practices across 30 cities, with realistic geography;
   - 5,000 doctors with availability for 30 days;
   - 200,000 patients;
   - 1M active reminder occurrences per day.
   Generated by a seeded script and stored in the repo with no real names. **Aadhaar-like values never appear.**
3. **External providers are replaced by their fakes** (adapter rule A10), with realistic latency and failure rates. **No load is ever sent to a real SMS, payment or video provider.**
4. Thresholds come from the Performance sheet. A run fails if any threshold is breached.

## 5. Mobile performance budgets (both apps)

**Reference low-end device:** Android Go class, 2 GB RAM, quad-core, Android 11 or later [CONFIRM]. **Mid device:** a current mid-range Android phone. iOS: the oldest supported iPhone.

| Budget | Target | How checked |
|---|---|---|
| **Cold start** (to the first usable screen) | **< 3 s on the low-end device** (Performance sheet) | Android Macrobenchmark; iOS XCTest launch metrics; in CI on a device farm or emulator profile, plus manual checks on a real low-end device each release |
| Warm start | < 1 s | Same |
| Download size | Patient app **< 30 MB** Android download size; Pro app < 40 MB [CONFIRM] | Store size reports; a CI check on bundle size grows no more than 5% per release without approval |
| Screen render | 60 fps target; no frame > 700 ms (frozen-frame threshold) on main flows | Platform profilers |
| Memory | < 200 MB on the low-end device in main flows | Profilers |
| Network | Home screen < 100 KB of API data; images resized and cached; works on a 3G profile (400 kbps, 400 ms latency) | Network throttling tests |
| Offline | Home and calendar render from cache; reminders fire (E-REM-02) | TC-40 |
| Crash-free sessions | ≥ 99.5% (staged rollout pauses below it) | Crash reporting (scrubbed) |
